**Milestone tag:** `b1-p1-expression-engine`

This is a capstone rather than a module, and the difference shows in the shape
of §B. There are no independent exercises: there are **five stages**, each
consuming the type the one before it produced, and they are built in order
because S2 cannot be tested before S1 exists.

**S3 is the one people skip and it is the one that matters.** It asks for
`size`, `depth` and `render` — four-line traversals with nothing conceptual in
them — and it exists so that the explicit-stack technique is learned where the
only thing that can break is a count. Skip it and you will meet the technique
for the first time in S4, inside an evaluator, where a defect is a wrong number
rather than a wrong total.

### B. Implementation — The Five Stages

- [ ] **S1 `Lexer.tokenize`.** Maximal munch for numbers and identifiers,
      whitespace discarded, errors as values carrying the character index.
      `Stage1LexerSpec` green.
- [ ] **S2 `Parser.parse`.** Precedence, left associativity for `+ - * /`,
      right associativity for `^`, unary minus between `^` and `*`, and the
      top-level check that the token list was consumed entirely.
      `Stage2ParserSpec` green.
- [ ] **S3 `Shape.sizeNaive`, `size`, `depth`, `render`.** `sizeNaive` is the
      control and is kept. `size` and `depth` are `@tailrec` over an explicit
      stack; `render` is allowed to stay recursive, and §E records its ceiling.
      `Stage3TraversalSpec` green.
- [ ] **S4 `Eval.applyOp`, `evalNaive`, `eval`.** Two stacks on the heap, one
      `@tailrec` loop, an instruction type that says what to do on the way back
      up. `evalNaive` is the control and is kept. `Stage4EvalSpec` green.
- [ ] **S5 `Simplify.simplify`, `simplifyFast`, `Engine.compile`,
      `Engine.evaluate`.** The sound rule set, the fast-math rule set kept
      separate and named, and the pipeline. `Stage5EngineSpec` green.
- [ ] The full suite green in one run: `sbt "fundamentals/testOnly
      cs.se.block1.project1.*"`.

- [ ] **No `case _ =>` catch-all in any match over `Expr`, `Op` or `Token`.**

### D. Purity Gate

- [ ] No `var`, no `while`, no `do`, no traditional `for` loop anywhere under
      `src/main/scala/cs/se/block1/project1/`.
- [ ] No `throw` and no exception construction anywhere in that directory.
      Every failure is a value in an `Either`.
- [ ] No `null`, no `Option.get`, no `Either.toOption.get`, no partial

- [ ] No mutable collection, no `Array` used as a scratch buffer, no

      required.
- [ ] The two experimental controls — `sizeNaive` and `evalNaive` — are the
      only functions in the project permitted to have a stack ceiling by
      accident. `render`'s ceiling is by *decision*, and §E records it.
- [ ] `Engine.evaluate` calls `simplify`, never `simplifyFast`. State here how
      you would expose the fast path to a caller who wanted it, and what the
      signature would have to say for that choice to be honest.

### F. Engineering Hygiene

- [ ] All code formatted (`sbt scalafmtAll`) with no manual override.
- [ ] Commits follow `docs/git-conventions.md` (`b1-p1: <imperative summary>`),
      one commit per stage, and a stage is not committed until its spec is
      green.
- [ ] `error-patterns.md` read before committing; any defect instantiating an
      existing pattern added as an occurrence rather than opening a new entry.
      Three of its patterns are near-certain to recur here:

      Pattern 11 — *a fixture that cannot exhibit the property under test.*
      `2 ^ 2 ^ 2` is `16` under both associativities and `2 + 3` is `5` under
      both operand orders. A suite built from commutative, self-inverse inputs
      tests nothing about the two things this project most easily gets wrong.

      Pattern 13 — *a measurement taken while its subject is still changing.*
      This project adds a second cause to it: sbt runs test classes in parallel
      in one JVM, so a ceiling measured during a full run shares its machine
      with four other suites. Read it before writing any assertion on a depth.

      And whatever the pattern for *an instrument that discriminates more
      finely than the property needs* is called by the time you get here —
      guide §38's `doubleToRawLongBits` is an occurrence of it, and if no entry
      covers it, open one.
- [ ] Annotated milestone tag `b1-p1-expression-engine` created, using the
      message template, with a real entry under `Learned:`. Created **after**
      §G.
